Claude + fm Benchmark

Can Apple's on-device model (fm) take work off Claude without losing accuracy? Yes for structured extraction, partly for classification, no for filtering text.

Why fm fails

Confidently wrong

"How do I add a new user to our team workspace?" was labelled feature_request, high confidence. The answer is account. fm's own confidence is no basis for deciding what to send to Claude.

Changes what it copies

Asked to copy ERROR lines, fm turned WARN retry lines into ERROR lines: 24 of 62 lines it returned (medium log) were altered.

WARN  retrying … code=E1042-retry
→ ERROR  retrying … code=E1042-retry

Misses items

It dropped 11 of 46 real error lines in the medium log. Claude can't recover what it never sees, which is why tandem is no better than fm on logs.

How to pair Claude and fm

  • Do: fm extracts into a fixed schema (--schema), code checks each field against the source, and Claude redoes only the records that fail. This kept accuracy at 99–100% for a tenth of the cost.
  • Only with a check: classification is cheap with fm, but decide what to send to Claude with something you can verify (rules, or two prompts that disagree), not with fm's confidence.
  • Don't: use fm to filter or copy text. grep does the log task perfectly for free, in milliseconds.
  • Expect it to be slower: the fm and tandem routes took 1.7–16× as long as Claude alone because its 4k-token context forces many small calls (64 for the large log).

Method

Models. Claude: claude-sonnet-5-5 via claude -p with a one-line system prompt and no tools. fm: Apple's on-device system model with greedy sampling.

Data. Synthetic inputs generated from fixed seeds, so every answer is known exactly. Classify: 12, 40 and 120 support tickets. Extract: 4, 15 and 40 invoice emails with decoy amounts and dates. Logs: 150, 1,000 and 3,000 lines with 3, 5 and 7 error codes to count.

Routes. Claude gets the whole input in one call. fm works in chunks that fit its context, and Python merges the results. Tandem runs fm first, then sends Claude only the tickets fm was unsure of, the emails that failed validation, or the log lines fm kept.

Measurement. Claude tokens come from the CLI's usage report (input, cache and output), including about 370 tokens of fixed overhead per call. fm tokens come from fm count-tokens. Accuracy: share of tickets right; share of the 5 fields per email right; for logs, the average of codes found, counts exact and first timestamps exact.

Limits. Every run gave the same result (fm is deterministic with greedy sampling, and Claude scored 100% each time), so the 3 repeats add no spread. The data is synthetic and cleaner than real mail or logs. Times are for this Mac.
